# Group Domain Guidelines

## Scope and Precedence

- 이 파일은 Group 도메인에만 적용한다.
- 저장소 루트 `AGENTS.md`와 `docs/project_code_convention/`의 규칙을 먼저 확인하고 따른다.
- 공통 규칙을 반복하지 말고, Group 도메인에 특화된 규칙만 추가한다.
- 기존 코드·명세·마이그레이션 사이에 차이가 있으면 임의로 정규화하지 말고 차이와 근거를 보고한다.
- 구현에 필요한 정책이 명세에 없거나 서로 충돌하면 임의로 결정하지 말고 확인이 필요한 항목으로 남긴다.

## Package Responsibilities

- 기존 `group` 도메인의 패키지 구조와 네이밍을 우선 확인하고 유지한다.
- Controller는 HTTP 요청과 응답을 연결하고, 도메인 유스케이스는 Service에서 처리한다.
- Service의 command/query 분리 방식은 루트 지침, 코드 컨벤션 및 기존 도메인 구현을 확인해 적용한다.
- Repository는 Group 도메인의 영속성 접근을 담당한다. 다른 도메인의 데이터 접근은 해당 도메인의 Repository나 Service를 사용한다.
- Converter는 실제 변환 책임이 있고 기존 컨벤션과 맞을 때 사용한다. 불필요한 변환 계층을 추가하지 않는다.
- DTO, Entity, Exception, Validation 타입은 각 패키지의 기존 구조와 컨벤션을 따른다.

## API Specification

- API 변경 시 구현과 테스트를 갱신하고, 합의된 명세 변경이 필요한 경우 저장소 루트의 `docs/api/group.md`도 함께 갱신한다.
- 구현·명세·마이그레이션 간 불일치는 임의로 수정하지 말고 차이와 근거를 보고한다.

## Domain Rules

- 그룹 생성·수정·폐쇄, 가입 신청·취소, 초대 생성·수락·폐기 동작은 명세와 기존 도메인 모델을 근거로 구현한다.
- 그룹 및 가입 신청에 대한 권한은 인증 사용자와 그룹 내 역할을 기준으로 검증한다. 역할 이름과 권한 범위는 실제 권한 모델 및 명세를 따른다.
- 그룹 공개 범위, 가입 정책, 정원 초과, 중복 가입·신청, 초대 만료·폐기 등은 명세에 정의된 동작만 구현한다.
- 그룹 폐쇄 시 데이터 보존·아카이빙·연관 데이터 처리 방식은 명세와 데이터베이스 제약을 함께 확인한다.
- Entity 연관관계와 삭제 동작은 기존 Flyway 마이그레이션, 외래 키 제약 및 전역 컨벤션과 일치시킨다. 필요한 변경이 있다면 마이그레이션과 테스트를 함께 검토한다.

## Search and Pagination

- 검색 필터, 정렬 옵션, 기본값, 커서 형식 및 페이지 크기는 API 명세를 따른다.
- 위치 기반 검색은 위치 정보가 제공된 경우에만 명세에 정의된 방식으로 적용한다. 위치 정보가 없거나 유효하지 않은 경우의 동작을 임의로 정하지 않는다.
- 커서 페이지네이션은 정렬 조건과 일관되게 동작해야 하며, 동률 처리와 다음 페이지 기준은 명세 및 기존 구현을 확인한다.
- 추천 점수 등 내부 계산값의 응답 노출 여부는 API 명세를 따른다.

## Validation and Exceptions

- 요청 검증 위치, 예외 구조, 성공·에러 응답 형식은 루트 지침과 코드 컨벤션 및 기존 도메인 구현을 따른다.
- Group 전용 오류는 기존 오류 코드 체계를 확장해 정의하고 공통 예외 처리 흐름을 우회하지 않는다.
- 권한 오류, 존재하지 않는 그룹·초대, 유효하지 않거나 만료된 요청의 처리는 API 명세의 상태 코드와 오류 응답을 따른다.

## Transactions

- 트랜잭션 경계는 루트 지침, 코드 컨벤션 및 기존 Service 구현을 확인해 적용한다.
- 여러 Entity나 연관 데이터에 걸친 변경은 원자성 및 외래 키 제약을 고려한다.
- 삭제·폐쇄 과정에서 여러 데이터 변경이 발생하면 하나의 유스케이스로서 일관성이 유지되는지 검토하고, 필요 시 통합 테스트로 확인한다.

## Tests

- Group API의 성공·실패·권한·검증·경계 조건을 테스트한다.
- 검색은 필터 조합, 정렬, 커서 경계 및 위치 정보 유무에 따른 동작을 명세 기준으로 검증한다.
- 가입과 초대는 중복 요청, 권한, 정원, 만료·폐기 등 명세에 정의된 주요 경우를 검증한다.
- 영속성, 트랜잭션, 연관 데이터 처리 또는 마이그레이션에 영향이 있으면 기존 테스트 관례에 맞는 통합 테스트를 추가한다.
- 테스트 프레임워크, 테스트 데이터 구성 및 검증 명령은 루트 `AGENTS.md`와 기존 테스트 관례를 따른다.
